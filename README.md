# Инструмент визуализации графа зависимостей (Вариант №4)

Консольное (CLI) приложение для анализа и визуализации графа зависимостей пакетов формата **JavaScript (npm)** без использования сторонних библиотек и штатных менеджеров пакетов.

---

## Этап 1. Минимальный прототип с конфигурацией

**Цель этапа:** создать минимальное CLI-приложение, считывающее пользовательскую конфигурацию из аргументов командной строки, выполняющее валидацию всех входных параметров и выводящее конфигурацию в формате `ключ: значение`.

### 1. Настраиваемые параметры командной строки

| Флаг CLI | Ключ в выводе | Обязательный | Описание и правила валидации |
| :--- | :--- | :---: | :--- |
| `--package` | `package` | Да | Имя анализируемого пакета. В обычном режиме проверяется по стандарту имён `npm` (строчные буквы, цифры, дефисы, опциональный `@scope/`). В тестовом режиме допускаются только заглавные латинские буквы (`A-Z`). |
| `--repo` | `repo` | Да | URL-адрес репозитория или путь к файлу тестового репозитория. В обычном режиме проверяется наличие схемы `http://` или `https://` и домена. В тестовом режиме проверяется физическое существование файла на диске (`os.path.isfile`). |
| `--test-mode` | `test_mode` | Да | Режим работы с тестовым репозиторием. Принимает строго значения `true` или `false`. |
| `--version` | `version` | Да | Версия пакета. Должна соответствовать формату семантического версионирования `X.Y.Z` (с возможным суффиксом, например `1.0.0-beta.1`) или ключевому слову `latest`. |
| `--output` | `output` | Да | Имя сгенерированного файла с изображением графа. Не должно содержать запрещённых символов ОС (`<>:"\|?*`) и обязано заканчиваться расширением `.svg`. |
| `--max-depth` | `max_depth` | Да | Максимальная глубина анализа зависимостей. Должна быть целым положительным числом (`> 0`). |
| `--filter` | `filter` | Нет | Подстрока для фильтрации пакетов. Если передана, не должна быть пустой и может содержать только буквы, цифры и символы `.`, `_`, `-`. |

### 2. Архитектура решения (Этап 1)

Код в файле `main.py` разделён на компактные модульные функции:
* `create_parser()` — инициализирует парсер `argparse.ArgumentParser` и регистрирует 7 опций командной строки.
* `validate_args(args)` — координирует вызов проверочных функций, собирает все найденные ошибки в единый список и при их наличии выводит сообщения в поток `sys.stderr`, завершая программу с кодом возврата `1`.
* `check_test_mode(val, errors)` — проверяет корректность флага `--test-mode` и возвращает булево значение режима работы.
* `check_package(pkg, is_test, errors)` — валидирует имя пакета в зависимости от выбранного режима (реальный `npm` или тестовый граф).
* `check_repo(repo, is_test, errors)` — проверяет корректность URL-адреса или существование локального файла тестового репозитория.
* `check_version_and_output(ver, out, errors)` — проверяет формат версии пакета и корректность имени выходного `.svg` файла.
* `check_depth_and_filter(depth_str, flt, errors)` — проверяет, что глубина является целым числом больше нуля, а подстрока фильтрации не содержит запрещённых символов.
* `main()` — точка сборки конфигурации и вывода параметров в формате `ключ: значение`.

### 3. Примеры запуска и демонстрация работы

#### Корректный запуск (обычный режим):
```powershell
python main.py --package express --repo https://registry.npmjs.org --test-mode false --version 4.19.2 --output graph.svg --max-depth 3 --filter debug
```

**Результат вывода:**
```text
package: express
repo: https://registry.npmjs.org
test_mode: False
version: 4.19.2
output: graph.svg
max_depth: 3
filter: debug
```

#### Демонстрация обработки ошибок для всех параметров:

1. **Ошибка режима работы (`--test-mode`):**
   ```powershell
   python main.py --package express --repo https://registry.npmjs.org --test-mode yes --version 4.19.2 --output graph.svg --max-depth 3
   ```
   *Вывод:* `Ошибка --test-mode: нужно 'true'/'false', дано 'yes'.`

2. **Ошибка имени пакета (`--package`):**
   ```powershell
   python main.py --package "INVALID_NAME!" --repo https://registry.npmjs.org --test-mode false --version 4.19.2 --output graph.svg --max-depth 3
   ```
   *Вывод:* `Ошибка --package: неверное имя 'INVALID_NAME!'.`

3. **Ошибка URL репозитория или пути к файлу (`--repo`):**
   ```powershell
   python main.py --package express --repo "ftp://bad-url" --test-mode false --version 4.19.2 --output graph.svg --max-depth 3
   ```
   *Вывод:* `Ошибка --repo: неверный URL 'ftp://bad-url'.`

4. **Ошибка версии пакета (`--version`):**
   ```powershell
   python main.py --package express --repo https://registry.npmjs.org --test-mode false --version "v1.0" --output graph.svg --max-depth 3
   ```
   *Вывод:* `Ошибка --version: неверный формат 'v1.0'.`

5. **Ошибка имени выходного файла (`--output`):**
   ```powershell
   python main.py --package express --repo https://registry.npmjs.org --test-mode false --version 4.19.2 --output graph.png --max-depth 3
   ```
   *Вывод:* `Ошибка --output: 'graph.png' должен быть '.svg'.`

6. **Ошибка максимальной глубины (`--max-depth`):**
   ```powershell
   python main.py --package express --repo https://registry.npmjs.org --test-mode false --version 4.19.2 --output graph.svg --max-depth -5
   ```
   *Вывод:* `Ошибка --max-depth: число должно быть > 0.`

7. **Ошибка подстроки фильтрации (`--filter`):**
   ```powershell
   python main.py --package express --repo https://registry.npmjs.org --test-mode false --version 4.19.2 --output graph.svg --max-depth 3 --filter "bad filter!"
   ```
   *Вывод:* `Ошибка --filter: недопустимая строка 'bad filter!'.`

## Этап 2. Сбор данных

### Цель этапа
Реализовать получение данных о прямых зависимостях пакета для заданной версии из репозитория формата `npm` без использования менеджеров пакетов и сторонних библиотек.

### Реализация
* **`build_package_url(repo, package, version)`** — формирует конечный URL к эндпоинту реестра вида `<repo>/<package>/<version>`.
* **`fetch_package_data(url)`** — выполняет HTTP GET-запрос средствами стандартной библиотеки `urllib.request`, декодирует JSON-ответ и перехватывает сетевые ошибки (`HTTPError`, `URLError`, `JSONDecodeError`).
* **`get_direct_dependencies(repo, package, version)`** — извлекает словарь прямых зависимостей из поля `"dependencies"` метаданных пакета.
* **`print_direct_dependencies(package, version, deps)`** — выводит список прямых зависимостей и их версий в консоль.

### Примеры запуска
Получение зависимостей пакета `express@4.19.2`:
```powershell
python main.py --package express --repo [https://registry.npmjs.org](https://registry.npmjs.org) --test-mode false --version 4.19.2 --output graph.svg --max-depth 3
```

## Этап 3. Основные операции *(в разработке)*

**Цель этапа:** построить полный граф зависимостей с учётом транзитивности и выполнить основные операции над ним.

* **План реализации:**
  * Реализация обхода графа алгоритмом **DFS с рекурсией**.
  * Ограничение глубины рекурсии значением `--max-depth`.
  * Исключение из анализа пакетов, содержащих подстроку `--filter`.
  * Защита от зацикливания при наличии циклических зависимостей.
  * Поддержка режима тестирования (`--test-mode true`) с чтением графа из локального файла, где пакеты обозначены заглавными латинскими буквами (`A-Z`).

---

## Этап 4. Дополнительные операции *(в разработке)*

**Цель этапа:** реализовать поиск и вывод на экран **обратных зависимостей** для заданного пакета (поиск пакетов, которые зависят от целевого) с использованием алгоритма обхода из Этапа 3 и демонстрацией на тестовом репозитории.

---

## Этап 5. Визуализация *(в разработке)*

**Цель этапа:** получить графическое представление графа зависимостей.

* **План реализации:**
  * Генерация текстового описания графа на языке диаграмм **Graphviz (DOT)**.
  * Рендеринг и сохранение итогового изображения в файл формата **SVG** (`--output`).
  * Демонстрация визуализации для трёх различных пакетов.
  * Сравнение полученных графов со штатными инструментами визуализации `npm` и анализ возможных расхождений.
